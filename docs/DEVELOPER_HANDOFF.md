# 새 개발자 채팅에 전달할 지시문

아래 내용을 새 채팅에 붙여 넣고 저장소 폴더를 작업 대상으로 선택한다.
이 문서는 개발 지시문이며 새 채팅이 자동 생성되거나 Notion 권한이 부여됐다는 뜻은 아니다.

> 당신은 Swing Only Golf의 개발 담당입니다. https://github.com/fresh-woo/Swing_Only-GOLF 저장소를 읽고 AGENTS.md, PRODUCT.md, CONTRIBUTING.md, docs/DEPLOYMENT.md와 연결된 Notion 구현 계획을 먼저 확인하세요. 현재 작업 상태와 브랜치를 확인하고 다른 채팅의 변경을 덮어쓰지 마세요. 동시에 작업하는 경우 별도 worktree를 사용하세요.
>
> 첫 목표는 빈손 스윙을 관찰하는 카메라 화면입니다. 카메라 켜기·끄기, 권한·장치·모델 오류, 관절 표시를 먼저 완성하고, 양쪽 팔꿈치의 굽힘·펴짐, 어깨 위치, 몸통·골반, 머리 움직임을 항목별로 표시하세요. 하체 사용은 후순위이며, 골반이 안 보이면 해당 항목만 판단 불가로 표시하세요. 실제 공 회전·볼 속도·골프채 속도 계측은 범위 밖입니다.
>
> MediaPipe의 신체 점을 활용하되 화면상 추정값을 실제 관절각·회전의 정밀 측정값으로 표시하지 마세요. 관찰값과 근거를 실제 영상과 대조하면서 한계를 한 가지씩 해결하세요. 머리는 스윙 전체에서 완전히 정지해야 한다고 점수화하지 말고 구간별 이동부터 보여주세요. 분석과 게임 결과·아이템 효과를 분리하세요.
>
> 첫 PR은 카메라와 관절 overlay를 작동시키는 작은 범위로 만드세요. 모델 파일과 WASM 경로는 Pages 하위 경로에서도 확인하고, 사용한 버전·모델 출처·조건을 기록하세요. 실제 캠을 테스트하지 못하면 그 한계를 명시하고 모의 입력과 구분하세요. npm run check 결과, 실행 방법, 화면 증거, 남은 한계를 PR에 남기세요. 세션에서 허용된 범위에 따라 검토·병합하고 main 직접 push나 임의의 운영 변경은 하지 마세요.

## 첫 PR의 완료 기준

- 캠 허용·거절·미검출·종료가 구별되고, 종료 시 카메라 트랙을 해제한다.
- 좌우 구분과 미러 표시가 일치한다. 필요한 신체 점을 화면에서 확인할 수 있다.
- 무릎·발이 안 보인다는 이유로 전체가 실패하지 않는다.
- 해당 PR에 포함한 각 관찰값의 입력·단위·신뢰도·판단 불가 상태를 설명한다.
- 계산 부분의 작은 테스트와 실제 화면 확인 기록이 있다.
- 분석이 아직 없는 카메라 PR은 분석 완료로 보고하지 않는다.

## 디자인과 협업

DESIGN.md는 제약이고 시각 스타일은 아직 미정이다.
디자인 채팅의 승인된 시안·상태 정의를 참고한다. 시안이 없어도 카메라와 계산 검증은 단순한 화면에서 진행한다.
새 사용자 결정은 Notion에 반영하고, 코드 사용법은 저장소에서 갱신한다.
